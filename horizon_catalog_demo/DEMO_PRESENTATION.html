Data Governance Policies

Five policy types provide defense-in-depth protection

PolicyWhat it doesApplied toKey design
Masking Hides/redacts column values by role SSN, Email, Phone, Address Tag-based: reads PII_LEVEL tag
Row Access Filters rows by department PATIENTS table Clinical staff sees only their dept
Aggregation Forces min group size = 5 BILLING table Prevents re-identification
Join Requires JOIN (no standalone SELECT) PATIENTS table Blocks bulk PII export for analysts
Projection Blocks SELECT of sensitive columns PRESCRIPTIONS.MEDICATION_NAME Prevents linking Rx to individuals

One masking policy + tags = automatic coverage across all PII columns. Uses IS_ROLE_IN_SESSION() for correct role hierarchy traversal.

Data Sharing & Agentic AI

Secure Data Sharing

  • Zero-copy: No data movement
  • Policies enforced: Consumers see only aggregated views
  • Pre-aggregated: Min 5 patients per group (no PII exposure)
  • Internal Marketplace: Publish as discoverable data product

Share contents: REVENUE_DASHBOARD + DEPARTMENT_METRICS

Cortex Agent

  • Semantic model defines metrics and dimensions in YAML
  • Natural language: "What is the no-show rate by department?"
  • Distributable: Package agent with the listing
  • Governed: Agent queries governed views only

Consumers get data AND the AI interface in one package
